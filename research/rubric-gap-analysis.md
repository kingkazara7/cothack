# 对题目要求的逐项自审

核对日期：2026-10-22。结论是：仓库已经形成可审计的研究原型，但**尚未完全满足**“全部 8 种方法均完成实际验证”的硬要求。

| 要求 | 当前状态 | 证据与缺口 |
|---|---|---|
| 5 种公开方法调研 | 基本满足 | P01–P05 均有技术原理、攻击目标、论文实验和公开链接；P02–P05 使用作者输入或模板回放 |
| 3 种自主攻击设计 | 基本满足，质量不均 | N01/N02 有威胁假设和双样例但仍是简单文本注入；正式 N03 已升级为 clean-input SAE latent injection，包含闭集 feature 选择、九档强度、norm-matched control、负方向和 thinking block 复核 |
| 每种至少 2 个实际测试样例 | 未完全满足 | P02–P05、N01、N02 与新 N03 均已运行；P01 因缺少可重放 block/signature 只有两个 `N/A` 计划，没有攻击请求，因此不能按题面算作完成 |
| 重点覆盖前沿模型 | 部分满足 | 有 Astra、GPT-5.6 Sol、DeepSeek、Qwen 网页实测和本地 Qwen3-8B 白盒实测；Fable 5.1 没有授权端点，网页模型不公开固定 checkpoint |
| 有效性和可靠性 | 部分满足 | 已区分成功、失败、无效候选、非特异激活退化、不可观测与未运行；N03 有九档强度和配对对照，但公开方法多数条件仍只有一次运行，不能估计可靠 ASR |
| 可复现性 | 较强但不完整 | 保存原始日志、输入哈希、源 row、代码提交和校验脚本；N03 保存 feature 选择分数、decoder/metadata 哈希与自动汇总，但没有提交 134 MB decoder；网页端 checkpoint 与参数仍不透明 |
| 错误归因 | 较强 | N03 没有把连续 `A` token 写成完整错误答案成功，而是分别报告答案注入 0/2、推理生成破坏 2/2；P03 无效谜题、P04 缺失 token 和 P01 未运行也分别处理 |
| 独立研究判断 | 较强 | 明确区分 raw CoT、网页可见推理、答案污染、拒答绕过与资源攻击；识别原论文 SAE checkpoint 缺失，构造可审计 fallback，并使用 feature-specific 对照区分 latent 劫持与普通激活崩坏 |

若以 10 分粗略衡量当前交付质量，约为 **7.5/10**：文献核对、证据保存、错误归因和正式 N03 白盒设计已经能体现前沿安全研究能力；硬性覆盖与统计强度仍不足。最关键的是 P01 仍为 `N/A`，所以不能宣称完全完成题面要求。

提交前优先级如下：

1. 给 P01 找到合法的可重放 reasoning block/signature 端点并做两例，或者更换为确实能运行的第五篇公开方法；只写“无法测试”不满足题面。
2. 提升 N01/N02：改用更复杂任务、增加消融与重复，而不是继续依赖两道简单算术题。
3. 每种方法增加重复运行或扩展到保留集，报告分母、置信区间和失败类别；两个固定样例只能称 PoC。
4. 对网页实验补齐可见模型标识、时间、参数、完整输入输出和截图/导出证据；无法取得的字段继续写 `N/A`。
5. 最终 README 只汇总已经完成的结果；计划、模拟和接口诊断必须留在独立状态列中。
