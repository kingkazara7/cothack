# 对题目要求的逐项自审

核对日期：2026-10-22。结论是：仓库已经形成可审计的研究原型，但**尚未完全满足**“全部 8 种方法均完成实际验证”的硬要求。

| 要求 | 当前状态 | 证据与缺口 |
|---|---|---|
| 5 种公开方法调研 | 基本满足 | P01–P05 均有技术原理、攻击目标、论文实验和公开链接；P02–P05 使用作者输入或模板回放 |
| 3 种自主攻击设计 | 部分满足，能力证据增强 | N01–N03 有威胁假设和双样例，但文本注入与简单算术仍偏弱；补充的 TRSS 已包含内部 feature 干预、正式测试样例与 SAE 训练隔离、独立 feature 排序集、三档强度、无关 feature 与方向对照，是更扎实的攻击设计，但尚未替换正式三方法之一 |
| 每种至少 2 个实际测试样例 | 未完全满足 | P02–P05、N01–N03 已运行；P01 因缺少可重放 block/signature 只有两个 `N/A` 计划，没有攻击请求，因此不能按题面算作完成 |
| 重点覆盖前沿模型 | 部分满足 | 有 Astra、GPT-5.6 Sol、DeepSeek、Qwen 网页实测和本地 Qwen3-8B 白盒实测；Fable 5.1 没有授权端点，网页模型不公开固定 checkpoint |
| 有效性和可靠性 | 部分满足 | 已区分成功、失败、无效候选、非特异激活退化、不可观测与未运行；TRSS 有强度扫描和对照，但正式公开方法每条件通常仍只有一次运行，不能估计可靠 ASR |
| 可复现性 | 较强但不完整 | 保存原始日志、输入哈希、源 row、代码提交和校验脚本；TRSS 保存训练输入、参数和 decoder 哈希，但没有提交 134 MB decoder；网页端 checkpoint、token 与采样参数仍不透明 |
| 错误归因 | 较强 | 没有把 P03 无效谜题算作防御成功，没有把 P04 缺失 token 当作 0，没有把 P01 不可运行写成失败；TRSS row 5 因无关 feature 同样退化而主动排除 |
| 独立研究判断 | 较强 | 明确区分 raw CoT、网页可见推理、答案污染、拒答绕过与资源攻击；识别作者 SAE checkpoint 缺失，构造可审计 fallback，并没有把一次普通激活退化包装成目标攻击成功 |

若以 10 分粗略衡量当前交付质量，约为 **7/10**：文献核对、证据保存、错误归因和 TRSS 白盒设计已经能体现前沿安全研究能力；硬性覆盖与统计强度仍不足。最关键的是 P01 仍为 `N/A`，所以不能宣称完全完成题面要求。

提交前优先级如下：

1. 给 P01 找到合法的可重放 reasoning block/signature 端点并做两例，或者更换为确实能运行的第五篇公开方法；只写“无法测试”不满足题面。
2. 将已经完成的 SAE/TRSS 正式替换 N01–N03 中最弱的一项，并同步八方法覆盖表、编号和总结果；否则它只能作为加分补充。
3. 每种方法增加重复运行或扩展到保留集，报告分母、置信区间和失败类别；两个固定样例只能称 PoC。
4. 对网页实验补齐可见模型标识、时间、参数、完整输入输出和截图/导出证据；无法取得的字段继续写 `N/A`。
5. 最终 README 只汇总已经完成的结果；计划、模拟和接口诊断必须留在独立状态列中。
